The workspace file format: a saved workspace written as APL you could have typed -- settings as the commands that set them, variables as assignments, functions as del definitions. Reading one back is therefore not parsing but running it, which the session already knows how to do, so the new apl-wsfile crate only writes; a workspace file is a sample and a sample is a workspace, which a reg-rs test shows by piping the fixture into the binary. Two things APL cannot say about itself travel as comment directives that the loader reads: when the workspace was saved, and where the random link stands so a loaded workspace carries on its sequence. Writing an array back exactly took care: a one-element vector is reshaped because a bare element is a scalar in APL, an empty array still needs something to reshape so it gets the fill, floats are written to as many figures as it takes to read the same number back, and minus and the exponent use APL's spellings. Names are sorted so the same workspace writes the same bytes every time. The state indicator is left out, recorded as a parity row rather than a silence: the saved half holds it, but a re-executable file cannot put execution back in the middle of a call, which APL\360's binary workspaces did not have to face. A locked function is written closed with del-tilde, the only way a text file can carry one, so the file shows what the editor refuses to -- locking guards the editor, not the file. Three tests pin it: the round trip through a real session, byte stability across repeated writes, and the file's shape against a fixture, so a format change must be a deliberate edit. The round-trip test caught a real APL trap while being written: its fixture is in origin 0, where iota of 1 is 0, so the familiar conditional branch idiom returns instead of looping. At the owner's request that became docs/index-origin-considerations.md, covering what the origin changes, why an APL\360 function cannot set its own, how people coped before the system variable existed, and why copying is riskier than loading -- the last being a requirement on step 3, recorded in plan.md, since a re-executable file cannot simply be run for a copy or it changes the origin under code already written. Also from the owner: ws/ is tracked and work/ is not, split by who wrote a workspace rather than what it is, since they are small UTF-8 text and size argues neither way. 262 Rust tests, 66 reg-rs tests, all gates clean.
