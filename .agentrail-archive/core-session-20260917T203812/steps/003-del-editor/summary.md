The del editor. Definition mode became the APL\360 editor: [n] repositions, [n] TEXT sets a line, [quad] displays the whole function framed by its dels, [n quad] displays from line n without the header, [delta n] deletes (DEFN ERROR if there is no such line), [0] is the header and [0] HEADER replaces it now, del closes renumbering from 1, del-tilde closes locked. Line numbers carry up to three decimal places, held as thousandths so an insert is exact, and the prompt steps at the grain the number uses ([1.5] is followed by [1.6]). Labels survive edits because they are read off the body at call time. Reopen with del-NAME (positioned after the last line); a command on the same line runs at once, so del-NAME[quad]del shows a function and returns to immediate execution. A locked function can be neither reopened nor displayed. A header naming something the workspace already holds is DEFN ERROR rather than a silent replacement; [0] may rename, which erases the old name rather than leaving a copy. New crate apl-editor (definition state, what an input line does, the bracket grammar) knows nothing of the workspace -- the session looks the function up, hands over a Defn, and stores what comes back; apl-ast gained Defn.locked, apl-scan gained header_text (the inverse of parse_header, which Phase 4's workspace file format will want), apl-workspace gained erase.
