The sign-off line, stopping a running function, and a pass over docs/session.md. )OFF now signs off the APL\360 way and exits 0: the time and date the session ended, then how long it was connected and what processor time it used, all from the clock step 6 installed; APL\360 also named the port and the user and carried totals to date, which sw-apl has no accounts for and says so. Ctrl-C stops a running function through a flag set from a signal handler that only stores it, read by a body between its lines, so INTERRUPT behaves as any other failure: it names the line, suspends the function, and the state indicator shows it for a branch to take up again. Verified end to end by sending SIGINT to a running loop, not only by the unit test. A body is read between its lines, so a statement that has not finished a line of its own cannot yet be stopped, which is recorded as a parity row rather than left silent; at a prompt Ctrl-C still cancels the line, because the editor holds the terminal in raw mode then and no signal is sent. Reading docs/session.md against the interpreter found two disagreements: Ctrl-D was documented as behaving like )OFF but only ended the loop, so it now signs off, and end of input ends the loop even in definition mode where )OFF would be a body line; and the sign-off section described one line where there are three, while the system-command tables read as a list of what works rather than of what the commands mean, both corrected in the doc with a pointer to parity.md for status. Two deliberate rebases: every sample ends with )OFF so every baseline gained the three sign-off lines, proved by copying the .out files first and diffing after with nothing else moved, and the step 7 filter gained the sign-off, which is the one varying output a sample cannot label because the session writes it rather than the program, with its shape kept and its values masked. Reply became a struct since both shells needed the same print-and-stop and an enum made each destructure it; the CLI is four modules again rather than five (main the command line, host the two consoles and the signal, repl the prompt loop, shell the batch loop), which error_lines moving down to apl-console made room for. The interrupt test lives in its own file and so its own process, because the stop flag is global as it must be to be set from a signal and cargo runs a file's tests on parallel threads; that took two goes to see, first the two interrupt tests racing each other and then one racing an unrelated test, and five consecutive runs of the suite are now clean. 266 tests, 47 transcripts, all gates clean.
