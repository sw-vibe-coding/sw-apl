The interpreter runs in a browser: apl-serve compiled to WebAssembly on a Web Worker, with Link implemented over a SharedArrayBuffer so recv parks the worker thread in Atomics.wait until the page posts a line. Console::read stays synchronous and Session is untouched. Built pages/ with a page, a module worker, and a service worker that gives the page the cross-origin isolation SharedArrayBuffer needs, since a static host will not send those headers. just pages builds it and just pages-serve serves it at 127.0.0.1:8361. Verified in a real browser: arithmetic, quad reading a line typed after the statement asked for it, the del editor with its bracketed prompts, and the I-beam clock. SAVE and LOAD report that there is no filesystem. Found and fixed a wasm trap with no message: Session::attached reads the clock at sign-on and SystemTime::now panics on wasm, so apl-ibeam now asks chrono for wasmbind on that target alone.
