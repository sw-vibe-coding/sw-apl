Implemented the manual's rule that only the first four characters of a command name are significant, so )CLEA, )CLEAR and )CLEAVER are one command and )ORIG 0, )DIGI 5 and )SYMB now work where they answered INCORRECT COMMAND. Pinned the three things the rule is not: it is not typo tolerance, since what follows the fourth character is ignored rather than forgiven; it is not prefix matching, since a name of four characters or fewer must be exact, so )VAR is not )VARS and )SI does not extend to )SIX; and it is not four bytes, since a command name may be any text and cutting at byte four would split a glyph. Nine commands are longer than four characters, no two agree in their first four, and no long command's first four spell a short command -- none of that is guaranteed by anything, so a test walks the list and asserts all three, which is what will notice when a command added later breaks the rule. canonical() went into command.rs, which was at its function budget, so sign_off folded into ending(); the two were always the same thing. The rule is applied once where the name is upper-cased, so the inquiry commands get it without apl-inquiry knowing it exists. 6 tests in a new apl-commands test crate, new sample 68-command-names, 77 reg-rs tests, parity row added, reference and session.md updated.
