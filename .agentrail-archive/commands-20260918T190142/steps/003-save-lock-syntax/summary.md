The step was meant to be about APL/360's password forms -- )SAVE took a lock and )LOAD a key after the name, sw-apl parsed neither, and )SAVE WS:PASS stored a workspace literally called WS:PASS. Probing what else a name could be found worse: a name went straight into a path with nothing checked, so )SAVE A/B made a directory, )SAVE .HIDDEN and )SAVE .. stored oddly named files, )SAVE /// tried to write at the filesystem root and leaked the OS error into the reply, and )SAVE ../../X wrote two directories above the library. One rule fixes all of it and is the historically right one: a workspace name is an APL name, which is what the lexer already requires of every other name. Checked in apl-library's file() before the name is joined to anything, so every command that takes one is covered at a single point, with )WSID held to the same rule separately. The reply is INCORRECT COMMAND, since the manual keeps that for a value out of range and reserves WS NOT FOUND for a well-formed name that is not stored. Lower case is accepted for consistency with the rest of sw-apl, recorded in parity.md along with the case-insensitive filesystem caution. 7 new tests, sample 65 extended and rebased, 77 reg-rs tests, all gates green.
