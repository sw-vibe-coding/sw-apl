Moved the CLI checks from Rust tests to reg-rs, per owner direction that reg-rs is for CLI regression testing in general. Thirteen checks moved: the version block, the help text, batch from stdin, the no-echo flag, a file run with -f, a missing file, invalid UTF-8, the bracketed definition prompt, a read fed from the script, the quote-quad prompt sharing a line with its answer, and the statement that ends an open line. cli_tests.rs is deleted and the binary now has no Rust test crate, because nothing left in it tested a library. Two were properties rather than transcripts and needed thought: each is now a command written to make its own answer the output, so the baseline is the word same or shorter. The version block names the machine, commit and moment it was built from, which no baseline can hold and the VARIES convention cannot reach because the binary prints them about itself and no program can label them; the filter masks those three values while keeping their field names, so a field going missing still fails. The wording of a missing file's error comes from the operating system and differs between them, so that is masked too, and its non-zero exit status is part of the baseline rather than an assertion, which is reg-rs recording what the Rust test had to check by hand. Proved rather than assumed: appending a line to the help text made the help test fail, and restoring it made it pass. 64 reg-rs tests now, 47 samples and 17 of the CLI, against 254 Rust tests, the twelve that moved being the difference. Two things reg-rs refuses are now written down so the next person does not find them the hard way: a description may not begin with a dash since clap reads it and takes it for a flag, and a command containing a pipe cannot be split out of a delimited list, which is why the seeding script calls a function per test instead of looping a table. docs/testing.md now opens with which tool covers what, and the gates there and in mw-cp.md ask for reg-rs on a CLI change rather than only an interpreter one.
