Overstrikes: forming an APL glyph by striking one character over another, as a 2741 did. The table of 17 pairs is in data/glyphs.toml with provenance per pair -- 8 quoted from the IBM 1968 and 1970 manuals, 3 mirroring a pair the manual states, 6 where the composite is visibly its parts -- and is generated into apl-value so the browser terminal will read the same one. The key is Ctrl-] and not Ctrl-H: Ctrl-H is 0x08, byte-identical to backspace, and rustyline binds it besides; 0x1D is free in rustyline, is not a terminal signal, and no known browser claims it. BACK and BACK_LABEL sit together so no help text can name an unbound key. apl-strike has a keystroke machine for typing and compose() for a line that arrives already typed, accepting 0x1D or the 0x08 a 2741 actually sent; either order forms the glyph, which is safe because no two pairs share their characters, checked by a test. An illegitimate overstrike is a CHARACTER ERROR naming both characters, which is the manual's own answer. The CLI composes before it echoes, so the paper shows the struck glyph. Two findings: the foundational character set is larger than the language's glyph set, since the 2741 carried intersection only so the lamp could be struck, which matters for printing keycaps; and del-tilde opens a locked definition as well as closing one, which sw-apl does not accept, recorded as step 005 rather than fixed here. Espanso and Emacs are untouched and stay first-class. 14 tests, new sample 71, 80 reg-rs tests, all gates green.
