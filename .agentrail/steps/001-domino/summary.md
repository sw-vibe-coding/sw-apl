Implemented domino, the last todo in the primitives table: monadic matrix inverse and dyadic least-squares matrix divide, in a new apl-prims-matrix crate. Found that it is not in the August 1968 manual at all -- it was added to APL/360 in 1970 -- and followed the APLX Language Manual for the same lineage, quoting the three passages that settle the rules. Householder QR rather than the normal equations, because the normal equations square the condition number and the overdetermined fit is the reason the glyph exists; the reflections are applied to the basis and the right-hand sides together so the factorisation is never stored. Shape rules: an axis from a vector or scalar is not in the answer, so a vector over a vector is the single coefficient that fits them, and a vector inverts to a vector. Singularity is a rank test at machine epsilon scaled by the problem size, deliberately not the comparison fuzz, and the code says why. The sample needed care: an earlier draft printed a floating-point identity check with 1e-15 noise, which would have been a baseline that could differ on another machine, so the example was chosen to be exact and the sample says so rather than implying floating point is exact. 15 tests, new sample 66-domino, 75 reg-rs tests, all gates green, sw-checklist 194 passed 0 failed.
