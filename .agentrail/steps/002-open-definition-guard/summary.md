Implemented NOT WITH OPEN DEFINITION, and the larger rule behind it. The parity row said a )COPY typed in definition mode should be refused; the manual says a system command entered during function definition will not be accepted as a statement in the definition at all, that some are rejected with report 6, and that most execute immediately. sw-apl had neither rule: a ) line became a body line, turning a mistyped command into a statement that failed later when the function ran. Now a command is looked for before an open definition takes the line; )FNS, )VARS and )ORIGIN run at once, and )SAVE, )COPY, )PCOPY and )CONTINUE are refused, with the guard canonicalising the name first so )CONT is refused too. Finding out why )LOAD has no report 6 turned up a bug the step did not go looking for: a load feeds the file's lines back through the session, and with a definition still open they went into the function rather than the workspace, so the file's contents vanished into a half-written function. The open definition belonged to the workspace being replaced and is now dropped with it, which is exactly the reason the manual exempts )LOAD. Also learned that a comment is a statement and does go in, which is why sample 70 keeps its narration outside the definition -- the first draft explained itself into the function it was demonstrating. 5 tests, new sample 70, 79 reg-rs tests, parity row split so the two remaining restrictions stand alone.
