1. APLCOURSE is effectively found

The best discovery is that a historical copy of APLCOURSE survives on the Michigan Terminal System distributions, and people have already demonstrated it running under Hercules.

The two user-facing functions are TEACH and EASYDRILL.

That is extremely close to the original IBM library-1 workspace documented in the APL\360 User's Manual:

)LOAD 1 APLCOURSE
APLCOURSE SAVED 07/19/68

)FNS
B1X CHECK DESCRIBE DIM DRILL DYAD1 DYAD2
EASY EASYDRILL FORM FUNDRILL GET INPUT
INTER LOG QUES RANDOM REDSCAPATCH REPP

The small differences in function set are probably version/platform differences rather than a fundamentally different course.

And the contemporary description confirms its purpose: TEACH generates APL expressions using scalars and vectors, while EASYDRILL restricts the generated exercises to simpler cases.

So your stated goal — “a new person could learn APL from scratch in my project” — has a historically authentic target rather than requiring you to invent an APLCOURSE-like system from descriptions.

5. The “Canadian repository” comment may be conflating several things

There are several Canadian APL preservation threads that could explain the recollection.

And )HELP becomes the user-facing doorway into the same taxonomy:

      )HELP DIALECT
      )HELP CLOCK
      )HELP RESTRICTIONS
      )HELP EXTENSIONS

It doesn't need to contain all the historical discussion.

One refinement: call it --environment, then allow overrides

Instead of accumulating:

--clock
--date
--terminal-count
--processor-time
--...

I'd define profiles first:

sw-apl --mode 75 --environment historical
sw-apl --mode 75 --environment host

TOML:

[emulation]
environment = "historical"

Then permit expert overrides only where useful:

[emulation]
environment = "historical"
clock = "host"

Internally something like:

EmulationPolicy
├── clock
├── date
├── cpu_time
├── terminal
└── multiuser

That gives you room for future cases without adding a command-line flag for every historical oddity.

My rule of thumb

Dialect selection determines language semantics. Emulation policy determines historically host-dependent behavior. Workspaces determine application state.

Keep those three orthogonal:

       DIALECT                 ENVIRONMENT
     --mode 70/75          --environment ...
          │                       │
          └──────────┬────────────┘
                     ▼
                  SESSION
                     │
                     ▼
                 WORKSPACE

And keep both dialect and emulation policy outside saved workspaces. That way loading BIRDS, LEARN, or eventually COURSE never changes the machine underneath the user's session.
