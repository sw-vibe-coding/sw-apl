Modeling the Rubik's Cube in array-oriented languages like APL, J, or BQN is a classic exercise in functional and mathematical elegance. Because array languages treat multidimensional data natively, a Rubik's Cube can be represented cleanly as an array rather than complex OOP pointers.
A notable project in this space is Eigencube by Steffen Smolka. It acts as a "functional pearl" that eschews traditional combinatorial lookup tables or permutation hacks. Instead, Eigencube models and solves the Rubik's Cube using discrete 3D rotation matrices and hyperplane dot products, mapping perfectly to array-based math.

1. Representing the Cube in APL

In APL, the most straightforward approach is to represent the cube as a 6×3×3 character array (representing 6 faces, each being a 3×3 grid of stickers).
Alternatively, a highly elegant mathematical representation uses 3D coordinates. If the individual cubies are tracked in a 3D grid (3 × 3 × 3), rotating a face simply means applying an array index permutation or a structural rotation along an axis.

How a Face Turn works in APL

When you turn a face on a Rubik's cube, two things happen:
1. The 3×3 grid of the face itself rotates 90°.
2. The adjacent edges of the surrounding faces shift.
In APL, a 90° clockwise rotation of a 2D matrix M can be written completely without loops or variables by combining matrix transposition (⍉) and reversal (⌽):
apl
rotate90 ← {⌽⍉⍵}
Use code with caution.
• ⍉⍵ transposes the matrix (swaps rows and columns).
• ⌽ reverses the columns, effectively yielding a perfect 90° clockwise turn.
To apply this to an entire 6-faced cube array C, you can target specific slices. For example, a function to turn the Top (U) face involves rotating C[1;;] and using vector rotation (⌽) to shift the top rows of the four adjacent faces.

2. The "Eigencube" Philosophy (Linear Algebra Approach)

If you move into languages heavily optimized for linear algebra or pure functions (like J, a modern dialect of APL, or NumPy/Julia), you can use the approach championed by Eigencube:
• Cubies as Coordinate Vectors: Every piece (cubie) on the Rubik's cube can be assigned a spatial vector in \(\mathbb{R}^{3}\), where \(x, y, z \in \{-1, 0, 1\}\).
• Stickers as Orthogonal Basis Vectors: The orientation of the stickers can be tracked by maintaining an orientation matrix for each cubie.
• Turns as Matrix Multiplications: Instead of tracking colors, a move is defined by an algebraic rotation matrix. For instance, turning the Right face clockwise by 90° means filtering out all cubies where x = 1, and multiplying their position and orientation vectors by:
\(\left(\begin{matrix}1&0&0\\ 0&0&-1\\ 0&1&0\end{matrix}\right)\)
• Slicing with Hyperplanes: In an array language, selecting which cubies to rotate is a simple conditional dot product or boolean mask (e.g., finding all elements where the dot product with the face vector equals 1).
